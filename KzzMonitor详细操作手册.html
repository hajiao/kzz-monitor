KzzMonitor 可转债监控系统详细操作手册

适用版本：1.x（Windows / macOS）
文档日期：2026-09-03

本工具用于个人数据整理和提醒，不构成任何投资建议。行情与评级来自第三方数据源，可能延迟、中断或变化。重要交易决定必须在券商终端复核。

1. 系统用途

KzzMonitor 是一个低频可转债监控程序。它可以：

  1. 按设定间隔轮询已启用的可转债；
  2. 获取现价、趋势、近一年最高价、监控峰值和强赎状态；
  3. 从“安道全”Excel 导入评级、建仓线、加仓线和重仓线；
  4. 触发建仓、加仓、重仓和卖出观察提醒；
  5. 通过桌面通知或 SMTP 邮件发送提醒；
  6. 根据中国交易日历、开盘、午休和收盘时间自动运行；
  7. 在系统托盘或 macOS 菜单栏后台驻留；
  8. 保存历史状态，重启后继续监控并避免短时间重复提醒。

2. 文件说明

2.1 Windows 便携版

建议把整个便携版解压到固定目录，例如：

D:\KzzMonitor\
├─ KzzMonitor.exe              主程序
├─ 可转债监控.xlsx              配置和结果面板
├─ KzzMonitor详细操作手册.html   离线网页手册
├─ KzzMonitor详细操作手册.pdf    PDF 手册
├─ install_startup.ps1         安装自动启动
├─ uninstall_startup.ps1       取消自动启动
├─ data\                       运行后产生的数据库和加密授权码
└─ logs\                       运行日志

运行不需要安装 Python，也不需要安装 Python 包。不要只复制 EXE；至少要让 EXE 和 Excel 工作簿处于同一目录。

2.2 macOS 版

macOS 应用首次运行后，实际数据保存在：

~/Library/Application Support/KzzMonitor/

控制台的“打开监控表”会打开正确的工作簿。不要直接修改应用包内部模板。

3. 第一次使用

3.1 Windows

  1. 解压便携包到固定目录；
  2. 双击 KzzMonitor.exe；
  3. 等待控制台出现；
  4. 点击“打开监控表”；
  5. 在“监控列表”中维护转债和策略参数；
  6. 在“设置”或控制台中设置轮询时间、安道全文件和通知；
  7. 保存并关闭 Excel；
  8. 回到控制台点击“立即强制新一轮”进行首次测试。

3.2 macOS

  1. 按住 Control 点击 KzzMonitor.app；
  2. 选择“打开”；
  3. 确认运行未签名的本地应用；
  4. 允许通知及钥匙串访问；
  5. 后续步骤与 Windows 相同。

4. 控制台说明

4.1 状态指示

状态 含义 是否需要处理
正在检查 正在读取配置、交易日历或市场状态 通常无需处理
监控正常 当前是交易时段，正在按顺序轮询 无需处理
等待开市 开盘前、午休、收盘后或非交易日 无需处理
异常重试中 网络、数据源或文件访问发生错误 查看运行日志
已停止 轮询线程已停止，控制台仍在 可点击“开启轮询”

4.2 操作按钮

开启轮询

启动常规监控。程序会自动遵守交易日、开市时间、午休和收盘时间。

结束轮询

停止轮询，但不关闭控制台。停止后不会继续获取行情，也不会发送行情提醒。

立即强制新一轮

忽略当前是否开市，立即完整处理全部已启用转债。每只转债之间仍遵守“轮询间隔秒”。适合：

  • 第一次配置后测试；
  • 临时手工刷新；
  • 收盘后核对数据；
  • 检查邮件和策略配置。

刷新安道全

立即读取设置的安道全文件，并按代码覆盖：

  • 当周评价；
  • 建仓线；
  • 加仓线；
  • 重仓线。

必须先选择安道全文件并保存设置。

保存设置

把控制台中的常用设置写入 Excel 的“设置”工作表。若 Excel 正在打开，Windows 可能锁定文件，应先保存并关闭 Excel。

测试邮件

先保存 SMTP 设置，再发送测试邮件。测试成功后检查收件箱和垃圾邮件目录。

测试桌面提醒

发送一条 Windows 通知中心横幅或 macOS 系统通知，用于检查系统通知权限。它不是阻塞式弹窗，不会暂停轮询；通知通常出现在屏幕右下角，并保留在 Windows 通知中心。

打开监控表 / 打开日志目录

分别打开当前真正使用的 Excel 配置表和日志目录。

4.3 关闭和后台运行

点击右上角关闭按钮时：

  • 选择“是”：停止轮询并彻底退出；
  • 选择“否”：隐藏到托盘/菜单栏，继续后台运行；
  • 选择“取消”：返回控制台。

托盘或菜单栏菜单可执行：显示控制台、启动、停止、强制新一轮、刷新安道全和退出。

同一系统用户只能运行一个实例。第二次启动会提示已有程序运行。

5. Excel 工作簿说明

程序写入工作簿时，Excel 应保持关闭。可以临时打开查看或修改，但查看完成后要保存并关闭。

5.0 控制台“监控面板”页

控制台第二个页面可直接查看监控结果，无需为了看行情而打开 Excel。表格每 5 秒从工作簿刷新，支持横向滚动，显示启用状态、代码、名称、现价、趋势、近一年最高价、监控峰值、回撤、仓位区域、三段线、评级、更新时间、强赎状态和运行说明。

下方编辑区支持：

  • 新增转债；
  • 选择已有行并修改启用状态、卖出参数、趋势参数、三段线和评级；
  • 删除选中转债；
  • 刷新结果；
  • 一键合并重复代码。

新增时会标准化 SH113043、SZ127027 等代码为六位数字。若代码已存在，“新增/保存”会更新第一条已有记录，不会创建重复行。删除操作需要二次确认，并删除该代码的全部重复行。

防呆校验包括：代码必须为六位数字；卖出观察价为正数；回撤比例在 0–100 之间；趋势窗口至少为 2；最小变动非负；已填写的三段线必须满足建仓线 ≥ 加仓线 ≥ 重仓线。

如果 Excel 已经存在重复代码，正常轮询只处理第一行并在日志警告，避免重复请求和重复提醒。“合并重复项”会保留第一行，用后续重复行补齐第一行的空单元格，然后删除其余重复行。

5.4 “使用说明”和“参数说明”工作表

内置精简操作指南、常见问题和参数解释，方便不打开外部手册时快速查看。

6. 两种轮询间隔

程序有两个不同层级的间隔，不能混淆。

6.1 轮询间隔秒：每查询一支转债的间隔

“轮询间隔秒”是每查询完一支转债后，到查询下一支转债前的等待时间，不是所有转债整体刷新周期。

例如启用 14 只转债，单只查询间隔设为 60 秒，忽略接口耗时，完成一整轮约需：

(14 - 1) × 60 秒 ≈ 13 分钟

最后一支完成后不再计一次单只等待，而是由“整轮间隔分钟”决定下一轮何时开始。

6.2 整轮间隔分钟：两轮启动之间的间隔

“整轮间隔分钟”按本轮开始时间到下一轮开始时间计算，不是“本轮完成后再等待这么久”。

例一：

  • 整轮间隔设为 60 分钟；
  • 第一轮 10:00 开始；
  • 第一轮 10:15 完成；
  • 程序再等待约 45 分钟；
  • 下一轮目标在 11:00 开始。

例二：监控数量很多：

  • 整轮间隔设为 60 分钟；
  • 第一轮 10:00 开始；
  • 第一轮直到 11:10 才完成，耗时 70 分钟；
  • 因为整轮耗时已经超过 60 分钟，整轮间隔不再产生额外等待；
  • 若当时仍处于允许的交易时段，程序直接开始下一轮；若已进入午休或收盘，则等待恢复交易。

可以概括为：

额外等待时间 = max(0, 整轮间隔 - 本轮实际耗时)

“立即强制新一轮”会打断整轮等待并马上启动一轮；这次强制轮询的开始时间会成为下一次整轮间隔的计算起点。

建议：

  • 单只查询间隔：10–20 只可设 30–60 秒，20–50 只可设 60–120 秒；
  • 整轮间隔：低频监控可设 30–60 分钟；
  • 不建议把单只间隔设置过低，以免增加数据源压力和限流风险。

7. 趋势与卖出提醒逻辑

7.1 趋势

程序读取最近“趋势窗口”次价格：

  • 首尾上涨达到“趋势最小跌幅”，且上涨步数不少于下降步数：上升；
  • 首尾下降达到阈值，且下降步数不少于上涨步数：下降；
  • 其他情况：震荡；
  • 数据不足：未知。

“趋势最小跌幅”虽保留旧名称，但实际同时作为上涨和下跌的最小绝对变化阈值。

7.2 卖出观察

需要同时满足：

  1. 程序记录到的监控峰值达到“卖出观察价”；
  2. 当前趋势为下降；
  3. 从监控峰值计算的回撤达到“回撤提醒%”。

回撤计算：

回撤% = (监控峰值 - 当前价) ÷ 监控峰值 × 100%

例如峰值 150，现价 141，回撤为 6%。若观察价为 130、回撤阈值为 5%，且趋势为下降，则触发卖出观察提醒。

同一轮下跌只提醒一次。回撤恢复到阈值的 40% 以下后解除锁定，下一次满足条件可以再次提醒。

这是“观察提醒”，不是自动交易指令。

7.3 三段线

按价格从高到低通常应满足：

建仓线 ≥ 加仓线 ≥ 重仓线

价格向下进入更深区域时提醒一次；从深区域反弹到浅区域不会发送新的建仓提醒。

8. 安道全数据导入

源工作表前 50 行内必须能找到：

  • 代码；
  • 建仓线；
  • 加仓线；
  • 重仓线；
  • 当周评价、当周评级或评级（三者之一）。

代码会去除 SH、SZ 前缀并统一为六位。- 会视为空值或零值处理。

建议每周拿到新文件后：

  1. 在控制台选择新文件；选择后路径会立即保存和回显；
  2. 程序自动读取文件中的工作表名称，在“安道全工作表”下拉框中选择目标表；选择后也会立即保存；
  3. 点击“刷新安道全”；
  4. 查看日志中的更新数量；
  5. 打开监控表抽查几只转债。

9. 邮件提醒设置

9.1 通用参数

  • 开启“邮件通知”；
  • 填写收件人；
  • 填写 SMTP 服务器、端口、用户名、发件人和授权码；
  • 选择 SSL；
  • 保存设置；
  • 点击“测试邮件”。

授权码不是邮箱网页登录密码，应在邮箱后台开启 SMTP 后单独生成。

邮箱 服务器 端口 SSL
QQ 邮箱 smtp.qq.com 465 开启
163 邮箱 smtp.163.com 465 开启

  • Windows：使用当前用户 DPAPI 加密，保存在 data/smtp_secret.bin；
  • macOS：保存在登录钥匙串，服务名为 KzzMonitor SMTP；
  • 换电脑或换系统用户后必须重新输入；
  • 不要把授权码写进 Excel、手册或截图。

11. 交易时间行为

默认按北京时间：

  • 09:30–11:30：轮询；
  • 11:30–13:00：暂停；
  • 13:00–15:00：轮询；
  • 15:00 后：根据设置执行最后一轮，然后等待下一天；
  • 非交易日：等待下一天。

程序在数据库中保存“上次完整轮询完成时间”，控制台顶部会持续显示。若今天是交易日、当前正处于午间休市，但最近一次完整轮询仍是昨天或更早，程序不会直接等到13:00，而会先补跑一轮完整轮询，完成后再保持午休等待。若今天上午已经完整轮询过，则午休期间不会重复补跑。

若交易日历接口失败，程序进入“异常重试中”，而不是仅凭星期误判开市。

12. 日志与故障排查

12.1 首先查看哪里

控制台底部显示实时日志。完整日志位于 logs/kzz_monitor.log。

12.2 常见问题

Excel 无法写入

原因通常是工作簿正在 Excel 中打开。此时监控和通知仍会继续，未写内容会持久化保存到数据库的“Excel 待写队列”：

  • 每只转债的普通行情结果只保留最新一条，避免工作簿长时间打开时累积大量过时快照；
  • 提醒记录逐条保留，不会因为后续行情覆盖而丢失；
  • 即使退出或重启程序，待写队列也仍然存在；
  • 保存并关闭 Excel 后，程序会在下一次处理转债前自动补写；
  • 日志出现“Excel 待写队列补写完成”表示已经清空。

因此无需为了查看 Excel 而停止监控，但建议查看后及时关闭，避免面板长时间不更新。

行情接口未返回某代码

程序会检查最后交易日。若历史最后交易日明显早于今天，会标记“可能已退市/停止交易”，而不是当成系统故障。建议停用该行。

异常重试中

可能是网络不可用、数据源限流、第三方接口字段变化或安道全路径失效。先查看日志中的最后一个异常。

邮件测试失败

检查服务器、端口、SSL、用户名、发件人、授权码和收件人；确认邮箱已开启 SMTP；检查防火墙和公司网络限制。

双击没有新窗口

可能已有实例在托盘/菜单栏运行。展开隐藏图标并双击 KZZ。全局单实例锁会阻止重复运行。

Windows 安全软件提示

PyInstaller 单文件程序会在临时目录解压运行，部分安全软件可能需要扫描或加入信任。只使用自己构建或可信来源的版本。

macOS 阻止打开

13. 数据备份与迁移

建议定期备份：

  • 可转债监控.xlsx；
  • data/monitor.db；
  • 必要时保留 logs。

迁移时先彻底退出程序，再复制文件。SMTP 授权码受操作系统当前用户保护，迁移后需要重新输入。

如果删除 monitor.db：

  • 监控峰值、短期趋势历史、提醒锁定和缓存会重置；
  • Excel 中的配置不会丢失；
  • 可能导致原本已提醒的条件再次提醒。

14. 推荐配置流程

  1. 先只启用 2–3 只有实时行情的转债；
  2. 设置 60 秒间隔；
  3. 暂时只开启桌面通知；
  4. 强制运行一轮，确认 Excel 更新；
  5. 导入安道全并抽查三段线；
  6. 配置并测试邮件；
  7. 再逐步启用完整列表；
  8. 稳定运行一到两个交易日后安装自动启动。

15. 版本更新注意事项

更新 EXE 或 .app 前：

  1. 从托盘/菜单栏彻底退出旧程序；
  2. 备份 Excel 和 data；
  3. 替换程序文件，不要覆盖自己已经配置好的 Excel，除非明确需要新模板；
  4. 启动新版本并执行一次强制轮询；
  5. 查看控制台日志。

15.1 在线更新（推荐）

配置“更新清单地址”后，程序可以在线检查和一键更新。更新过程：

  1. 读取 update-manifest.json；
  2. 比较当前版本和发布版本；
  3. 用户确认后下载对应 Windows/macOS 更新包；
  4. 校验 SHA-256，校验失败绝不安装；
  5. 自动退出当前程序；
  6. 替换程序和手册；
  7. 自动重新启动。

在线更新不会覆盖：

  • 可转债监控.xlsx；
  • data/monitor.db；
  • SMTP 加密授权码或 macOS 钥匙串；
  • logs；
  • 用户已有的监控参数和提醒记录。

新版本需要增加 Excel 配置项或帮助页时，会在首次启动时执行原地迁移：只补充缺少的字段，不覆盖已有值和监控列表。因此日常更新不需要重新发送 Excel。

15.2 发布者如何发布 Windows 更新

在开发工程完成构建后运行：

.venv-build\Scripts\python.exe make_windows_update.py --base-url https://你的地址/kzz-updates --notes "本次更新说明"

会在 updates 目录生成：

update-manifest.json
KzzMonitor-update-v版本-windows-x64.zip

更新 ZIP 只包含程序和手册，不包含 Excel。把这两个文件上传到同一个 HTTPS 目录，然后只需最初一次让使用者在控制台填写清单 URL。例如：

https://你的地址/kzz-updates/update-manifest.json

以后发布新版本时覆盖清单并上传新的版本 ZIP 即可，使用者不再需要接收完整便携包。

也可以把两个文件放在所有人可访问的公司共享目录，清单地址填写 UNC 路径，例如：

\\server\share\kzz-updates\update-manifest.json

若使用 GitHub，可把更新包放到 Release，把清单中的包 URL 写成 Release 下载地址，再把清单放到一个稳定的 Raw URL。GitHub 私有仓库需要身份认证，当前简易更新器不接收 GitHub Token，建议使用公开发布页或受控的内部 HTTPS/共享目录。

工程已附带 GitHub Actions 工作流 release-windows.yml。将工程放入公开 GitHub 仓库并推送版本标签（例如 v1.2.0）后，它会自动构建、测试并发布完整便携包、增量更新包和清单。使用者只需最初设置一次稳定地址：

https://github.com/你的用户名/你的仓库/releases/latest/download/update-manifest.json

15.3 “热更新”的边界

配置、监控列表、安道全数据和通知参数可以在运行中重新读取；但 EXE 或 .app 的代码不能在进程运行时直接替换，因此安装程序更新时会自动重启一次。这属于一键在线更新，而不是完全无重启的代码热替换。

16. 快速检查清单

  • [ ] 监控列表代码正确且仍有实时行情；
  • [ ] 需要监控的行“启用”为 TRUE；
  • [ ] 已区分“单只查询间隔”和“整轮启动间隔”；
  • [ ] 卖出观察价和回撤比例符合个人规则；
  • [ ] 建仓线 ≥ 加仓线 ≥ 重仓线；
  • [ ] 安道全路径有效；
  • [ ] Excel 已保存并关闭；
  • [ ] 控制台状态为“监控正常”或合理的“等待开市”；
  • [ ] 测试邮件成功；
  • [ ] 托盘/菜单栏图标可呼出控制台；
  • [ ] 自动启动在最终目录安装；
  • [ ] 已备份 Excel 和数据库。
